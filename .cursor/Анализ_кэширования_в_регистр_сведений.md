# Анализ проекта: кэширование в регистр сведений ikon_cost_ДетализацияЗатратСебестоимости

**Дата анализа:** 18.02.2025  
**Методология:** Последовательный анализ субагентами (Архитектор → Аналитик)

---

## Часть 1. Анализ Архитектора

### 1.1 Текущее состояние метаданных

#### Регистр сведений `ikon_cost_ДетализацияЗатратСебестоимости`

| Свойство | Значение |
|----------|----------|
| Периодичность | Месяц |
| Режим записи | Независимый |
| MainFilterOnPeriod | true |

**Измерения (ключ записи):**
- `Период` (стандартное для периодического регистра)
- `Организация`, `ПартияПродукции`, `АналитикаУчетаПартийПродукции`
- `Уровень`, `Номенклатура`, `Характеристика`, `Серия`
- `ПартияЗатрата`, `АналитикаУчетаПартийЗатрата`
- `ТипЗатрат`, `Подразделение`

**Реквизиты (служебные):**
- `ВерсияРасчёта` — инвалидация при изменении алгоритма
- `ДатаРасчёта` — аудит
- `ТребуетсяРазузлование`, `ТребуетсяРазузлованиеДопРасходов`, `ИдентификаторСтроки`

**Ресурсы:** 30+ полей (КоличествоЗатрата, СуммаЗатрата, Материальные, Трудозатраты и т.д.)

#### Связи метаданных

```
СтруктураСебестоимости (расчёт)
        │
        │ ЗаписатьРезультатВКэш()
        ▼
ikon_cost_КэшированиеРасчётов
        │
        ├── ЕстьДанныеВКэше(Период, Версия)
        ├── ЗаписатьРезультатВКэш(МенеджерВТ, Период, Версия, ...)
        ├── ПолучитьДанныеИзКэша(Период, НастройкиОтчета, ...)
        └── ОчиститьКэшЗаПериод(Период)
        │
        ▼
РегистрСведений.ikon_cost_ДетализацияЗатратСебестоимости
        │
        │ JOIN
        ▼
Справочник.КлючиАналитикиУчетаНоменклатуры (для Продукция из АналитикаУчетаПартийПродукции)
```

### 1.2 Алгоритм работы (текущая реализация)

```
Отчёт ФактическаяСебестоимостьПродукции (prod_cost_ext)
        │
        ├── ПериодРасчёта = НачалоМесяца(НачалоПериода)
        ├── ВерсияКэша = ВерсияАлгоритмаРасчёта()  // "v0.1.1.242"
        │
        ├── ЕстьДанныеВКэше(ПериодРасчёта, ВерсияКэша)?
        │
        ├── ДА → ПолучитьДанныеИзКэша() → ВнешниеНаборыДанных (Факт, Выпуски)
        │
        └── НЕТ → СтруктураСебестоимости.ЗаполнитьДеревоСебестоимости()
                        │
                        └── ЗаписатьРезультатВКэш() (после успешного расчёта)
```

### 1.3 Выводы Архитектора

**Реализовано корректно:**
- Структура регистра соответствует выходным данным алгоритма
- Версионная инвалидация (ВерсияРасчёта) — при смене версии алгоритма кэш считается устаревшим
- Запись с группировкой и сверткой дубликатов
- Отборы отчёта (Организация, Продукция, ПартияПродукции) применяются при чтении из кэша

**Выявленные пробелы:**

| № | Проблема | Критичность |
|---|----------|-------------|
| 1 | `ОчиститьКэшЗаПериод()` экспортирована, но **нигде не вызывается** | Высокая |
| 2 | Нет подписок на события изменения документов (расчёт себестоимости, выпуск и т.д.) | Высокая |
| 3 | Нет регламентного задания для предрасчёта кэша | Средняя |
| 4 | Нет UI для принудительного пересчёта кэша за период | Низкая |

**Риск:** При изменении первичных документов (выпуск, списание, расчёт себестоимости) кэш не инвалидируется. Отчёт может показывать устаревшие данные до следующего изменения версии алгоритма.

## Часть 2. Анализ Аналитика

### 2.1 Соответствие реализации требованиям

| Требование | Статус |
|------------|--------|
| Кэш хранит результат расчёта детализации затрат | ✅ |
| Ускорение повторного формирования отчёта | ✅ |
| Инвалидация по версии алгоритма | ✅ |
| Инвалидация при изменении исходных данных | ❌ Не реализована |

### 2.2 Рекомендации по доработке

#### Рекомендация 1: Инвалидация при изменении данных (приоритет: высокий)

**Вариант А — Подписка на события:**
- Подписаться на проведение/отмену документов расчёта себестоимости
- При проведении: вызвать `ОчиститьКэшЗаПериод(НачалоМесяца(ПериодДокумента))`
- Сложность: требуется определить полный список документов, влияющих на себестоимость

**Вариант Б — Регламентное задание:**
- Ежедневно/еженедельно очищать кэш за текущий и предыдущий месяц
- Проще в реализации, но возможны «окна» устаревания

**Вариант В — Комбинированный:**
- Подписка на ключевые документы + регламентная очистка за закрытые месяцы

#### Рекомендация 2: Регламентное предрасчёт (приоритет: средний)

- Создать регламентное задание, вызывающее отчёт (или прямой расчёт) за текущий месяц
- Время: ночное, низкая нагрузка
- Эффект: первый запрос пользователя утром уже идёт из кэша

#### Рекомендация 3: UI для пересчёта (приоритет: низкий)

- Добавить команду/обработку «Пересчитать кэш за период»
- Вызов: `ОчиститьКэшЗаПериод(Период)` + при необходимости принудительный расчёт

## Часть 3. Техническое задание для доработки (по запросу)

Если требуется реализовать инвалидацию при изменении данных:

### 3.1 Метаданные

- **Подписки на события** (или обработка регламентного задания)
- Вызов: `ikon_cost_КэшированиеРасчётов.ОчиститьКэшЗаПериод(Период)`

### 3.2 Документы для подписки (типовой 1С:ERP)

Необходимо уточнить в типовой конфигурации:
- Документы расчёта себестоимости
- Документы выпуска продукции
- Документы списания/операции

### 3.3 Функции для реализации

1. **В модуле расширения** (новый общий модуль или подписка):
   - Обработчик `ПередЗаписью`/`ПриЗаписи` документов → `ОчиститьКэшЗаПериод(НачалоМесяца(ДатаДокумента))`

2. **Регламентное задание** (опционально):
   - Процедура: вызов `ОчиститьКэшЗаПериод` за вчера и сегодня
   - Расписание: ежедневно, 02:00

## Заключение
